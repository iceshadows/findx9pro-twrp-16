# 02 前置条件

移植 TWRP 的三个硬前提，缺一个都做不下去。

## 1. Bootloader 解锁

**OPPO 主品牌（Find 系列）不提供小米那种公开的一键解锁通道。** 国行机型历史上只有少数批次
通过 ColorOS 社区的「深度测试 / 解锁申请」开放，且需报名审核、有名额和冷却期，海外版与国行
规则往往不同。**一加的解锁政策不能套用到 Find X9 Pro 上。**

先确认本机状态：

```bash
adb reboot bootloader
fastboot devices
fastboot oem device-info          # 看 unlocked 相关字段（不同版本命令可能不同）
# 或直接试
fastboot flashing unlock
```

判断标准很简单：**能否 `fastboot flash vendor_boot` 成功**。如果返回
`Flashing is not allowed` / `Not allow to flash` / 需要签名，说明未解锁，后面的步骤全部无法验证。

> 本工程不提供、也不评价任何绕过 BL 锁的方法。请通过官方或自己确认可行的途径解锁。

解锁的代价（务必知情）：清空数据、影响保修、支付/银行类 App 与 NFC 可能降级、
OTA 方式改变、变砖风险。

## 2. 官方固件

**这是本工程最关键的输入**，因为所有板级参数（DTB、load address、page size、cmdline、
分区大小）都必须从官方镜像里读出来，不能猜。

需要的镜像（至少前两个）：

| 文件 | 用途 |
|---|---|
| `vendor_boot.img` | **必需**。DTB、板级参数、官方 vendor ramdisk、分区大小 |
| `boot.img` | 可选。取 os_version；也是回滚备份 |
| `vbmeta.img` / `vbmeta_system.img` | 刷机时要关闭校验 |
| `dtbo.img` | 对齐 dtb 用（通常不是必需） |

**必须与实机同代**：vendor_boot 里带的是 DTB 和 MTK 内核模块，刷错代的镜像会卡开机。
本工程里有两份固件，取哪一份看实机当前跑的版本：

| 目录 | 代次 | 说明 |
|---|---|---|
| `ota_full/images_16/` | **Android 16**（整包镜像） | 当前基线 |
| `ota_full/images/` | 更新版（OTA `payload.bin`，`android_version=17`） | DTB/ramdisk 与 A16 不同，不要混用 |

两代固件解析出的板级参数（`board_config.local.mk`）和 `recovery.fstab` **完全相同**，
所以换基线只需重跑一次 `extract_stock.py`，设备树不用改。

注意 `images_16/` 是**部分镜像集**：有 `vendor_boot`/`boot`/`vbmeta*`/`dtbo`，
但没有 `init_boot.img`（本机确实有 `init_boot` 分区，`recovery.fstab` 里有）。
TWRP 不需要动 init_boot，但如果以后要整机回滚，记得补齐这一份。

获取途径（自行选择）：
- ColorOS 官方完整包（`.ozip`）。**注意 ozip 是加密的**，需要先解密再解包
  （社区有 `ozipdecrypt` / `oppo_ozip_decrypt` 类工具），然后从解出的 `images/` 里取。
- OTA 包里的 `payload.bin`（社区有 `payload-dumper-go` 等提取工具）。
- 或者从**已解锁的机器**上直接 dd 出来：
  ```bash
  adb shell su -c 'ls -l /dev/block/by-name/ | grep -E "vendor_boot|boot|vbmeta"'
  adb shell su -c 'dd if=/dev/block/by-name/vendor_boot_a of=/sdcard/vendor_boot.img'
  adb pull /sdcard/vendor_boot.img
  ```
  （A/B 机型注意取 `_a` 还是 `_b`，第一次移植用当前活动槽。）

放好后直接跑：

```bash
python3 tools/extract_stock.py --firmware-dir ota_full/images_16 --device-tree device/oppo/PLG110
```

脚本会打印解析结果并生成 `local-inputs/`。**先看 `local-inputs/vendor_boot_info.json` 对不对**
（header version 应为 4，page size 一般为 4096，cmdline 非空，DTB 大小非 0）。

## 3. Linux 构建环境

AOSP 从 Android 10 起就不再支持 macOS 编译，本机（darwin/arm64）只能做工具和准备，
**编译必须上 Linux x86_64**。三选一：

| 方案 | 说明 |
|---|---|
| GitHub Actions | 仓库自带 `.github/workflows/build-twrp.yml`，给个固件直链即可云端出包。最省事 |
| 本机容器 | macOS 上装 colima/docker，跑一个 ubuntu:22.04 + 必要依赖；需留 ~150G 磁盘 |
| 远程 Linux 服务器 | 装 `repo`/`git`/`openjdk-17`/AOSP 依赖包，直接跑 `tools/build_twrp.sh` |

要求：磁盘 ≥ 150 GB 可用（源码 ~50G + out ~60G），内存 ≥ 16 GB（32 GB 更稳），x86_64。

本机当前可用磁盘约 320 GB，若走容器方案注意别把 macOS 系统盘塞满。

## 4. 测试与回滚准备

```bash
# 刷之前先把官方镜像备份好，这是唯一的回滚手段
mkdir -p backup
cp ota_full/images_16/vendor_boot.img boot.img vbmeta.img vbmeta_system.img backup/
(cd backup && shasum -a 256 *.img > sha256sums.txt)

# repack 还要用它做合并基底
cp ota_full/images_16/vendor_boot.img \
   device/oppo/PLG110/local-inputs/stock_vendor_boot.img
```

本仓库当前已按 A16 基线做好（`backup/` + `backup/sha256sums.txt`），换固件时重做一遍即可。

变砖时的救砖手段：MTK 平台可用 SP Flash Tool（需 scatter 文件与 DA），
或进入 fastboot 刷回官方 vendor_boot。**务必先确认救砖路径再动手。**
