# 04 设备适配待办

首版目标是「能进 TWRP + 能挂载分区」。下面按优先级列出后续必须逐项做的设备适配，
每项都给了定位方法，**不要凭猜填参数**。

## P0：能进界面就能立刻发现的问题

### 1. 触摸不工作 / 坐标错乱

- 现象：界面能动但点不到，或完全没反应。
- 定位：
  ```bash
  adb shell getevent -pl                    # 列出所有 input 设备
  adb shell cat /proc/bus/input/devices
  adb shell dmesg | grep -iE "touch|goodix|focaltech|synaptics|novatek"
  ```
- 处理：
  - MTK/OPPO 机型常见有 `hbtp_vm` 之类的**虚拟输入设备**会和真实触摸抢事件，
    在 `BoardConfig.mk` 里加：
    ```make
    TW_INPUT_BLACKLIST := "hbtp_vm"
    ```
  - 需要额外驱动模块时，从官方 vendor ramdisk（`local-inputs/vendor_ramdisk/`）里
    挑出触摸相关 `.ko`，在 `rootdir/init.recovery.PLG110.rc` 里 insmod。
- 参考：官方内核源码里 `oppo-source/android_kernel_oppo_mt6993` 的触摸驱动与 DTS 节点。

### 2. 背光 / 亮度

- 定位：
  ```bash
  adb shell 'ls /sys/class/leds/'
  adb shell 'cat /sys/class/leds/lcd-backlight/max_brightness'
  ```
- 处理：改成实机路径与量程，例如
  ```make
  TW_BRIGHTNESS_PATH := "/sys/class/leds/lcd-backlight/brightness"
  TW_MAX_BRIGHTNESS := 2047
  TW_DEFAULT_BRIGHTNESS := 1024
  ```
  （当前 `BoardConfig.mk` 未启用这几项，先用 TWRP 默认值试。）

### 3. 屏幕方向 / 分辨率 / 颜色

- 若画面是紫绿反色，改 `TARGET_RECOVERY_PIXEL_FORMAT`（当前 `RGBX_8888`，
  可依次试 `RGB_565`、`ABGR_8888`）。

## P1：实用功能

### 4. FBE 解密（能读 /data）

这是移植里最麻烦的一块。当前 `BoardConfig.mk` 已开：

```make
TW_INCLUDE_CRYPTO := true
TW_INCLUDE_CRYPTO_FBE := true      # twrp-16.0 里真正拉进 FBE 组件链的开关
```

（核对过 twrp-16.0 的 `prebuilt/Android.mk` 与 `Android.bp`：`TW_INCLUDE_CRYPTO_FBE` 会把
`libtwrpfscrypt`、`keystore2`（V3/V4/V5-ndk）、`keymint`、`gatekeeper`、`fscryptpolicyget`、
`weaver` 等编进来。旧的 `TW_INCLUDE_FBE` / `TW_INCLUDE_FBE_METADATA_DECRYPT` 在
twrp-16.0 中**已不存在**，写了也不会被消费，所以已从设备树移除。）

真正解密还需要下面这些 vendor HAL 能在 recovery 里起来：

| 组件 | 作用 | 定位方法 |
|---|---|---|
| `keymint` / `keymaster` | 派生解密密钥 | `adb shell ls /vendor/bin/hw/ \| grep -iE "keymint\|keymaster"` |
| `gatekeeper` | 校验用户凭据 | `adb shell ls /vendor/etc/init/ \| grep -i gatekeeper` |
| `weaver` | 防暴力破解 | 同上 |
| `tee-supplicant` | MTK TEE 通道 | `adb shell ls /vendor/bin/tee-supplicant` |

做法：把实机上的 service 定义原样搬进 `rootdir/init.recovery.PLG110.rc`
（当前文件里是带 TODO 的注释模板），并确保对应 `.rc` 的 SELinux 标签在 recovery 策略里放行
（可能需要 `BOARD_VENDOR_SEPOLICY_DIRS` 加一个 `sepolicy/` 目录）。

**fscrypt 策略版本（待核实）**：官方 `/vendor/etc/fstab.mt6993` 里 `/data` 是
`fileencryption=aes-256-xts:aes-256-cts:v2+inlinecrypt_optimized`，即 **fscrypt v2 策略**。
现代 TWRP 设备树常配 `TW_USE_FSCRYPT_POLICY := 2`，但我没在 twrp-16.0 源码里定位到它的
消费点，**不要在首版盲加**：等能进界面后先看解密日志，确认是策略版本问题再加，并记录结论。

**首版可以先不做**：不解密也能刷 boot/vendor_boot 分区、做备份，
只是 `/data` 会显示为加密、不能读写用户数据。

### 5. fstab 与 ColorOS 专有逻辑分区

- 打开 `device/oppo/PLG110/recovery.fstab`，对照
  `local-inputs/stock-fstab/` 与实机 `/vendor/etc/fstab.mt6993`，
  决定是否启用 `my_bigball`/`my_product`/`my_heytap` 等分区。
- 刷 system/vendor 前要确认 `super` 剩余空间与槽位逻辑，别乱动 `super`。

### 6. USB / ADB / MTP

- 若 `adb devices` 认不到：`TW_USE_NEW_MINADBD` 在 twrp-16.0 里已写死在
  `Android.bp` 的 cflags（设备树不用也不该再设，已移除），先看
  `dmesg | grep -i configfs` 与 `TW_EXCLUDE_DEFAULT_USB_INIT` 是否需要去掉。
- 电脑端驱动：macOS 直接可用；Windows 需 OPPO 或 Google USB 驱动。

## P2：打磨

- `TW_THEME` / 语言包确认中文显示正常。
- 关机充电动画、电量显示（`TW_NO_BATT_PERCENT`）。
- 截图、日志导出路径。
- 确认 `twrp` 的 `vendor_boot` 在**两个槽**都能启动（第二槽启动能力是
  参考项目明确记录过的坑）。
