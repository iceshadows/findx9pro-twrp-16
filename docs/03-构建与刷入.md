# 03 构建与刷入

## 步骤 0：自检

```bash
python3 tools/selftest.py
```

会用手工按 AOSP `bootimg.h` 规范构造的 vendor_boot v4 验证解析/重打包，
并用系统 `lz4` 校验 LZ4 解码，这两项不依赖固件。

如果 `ota_full/images_16/`、`ota_full/images/` 或
`device/oppo/PLG110/local-inputs/stock_vendor_boot.img` 存在，还会对**真实官方镜像**做
回归：把解析出来的片段原样重打包，结果必须与官方镜像的有效内容**逐字节相同**，
且长度必须等于 avbtool 在尾部 footer 里记录的 `original_image_size`
（这一条同时覆盖了 header 偏移、片段紧邻拼接、页对齐、table/bootconfig 位置与补齐、
以及 `dtb_addr` 必须保留官方原值等全部关键约定）。**先跑通再动编译。**

## 步骤 1：生成板级输入

```bash
python3 tools/extract_stock.py \
    --firmware-dir ota_full/images_16 \
    --device-tree device/oppo/PLG110

# repack 需要官方 vendor_boot 原件（同时充当回滚备份）
cp ota_full/images_16/vendor_boot.img \
   device/oppo/PLG110/local-inputs/stock_vendor_boot.img
```

`--firmware-dir` 指向**与实机同代**的固件目录：本工程里 `ota_full/images_16` 是
Android 16 整包（当前基线），`ota_full/images` 是从 OTA `payload.bin` 解出的更新版
（`android_version=17`）。两者 DTB 与 vendor ramdisk 不同，不可混用。

产出：

```
device/oppo/PLG110/local-inputs/
  board_config.local.mk     ← BoardConfig.mk 会 include 它
  dtb.img / dtb             ← BOARD_PREBUILT_DTBIMAGE_DIR 用
  vendor_boot_info.json
  vendor_ramdisk/           ← 官方 vendor ramdisk 片段（含 MTK 内核模块）
  stock-fstab/              ← 从 ramdisk 捞出的官方 fstab 原文
  stock_vendor_boot.img     ← 官方 vendor_boot 原件（repack 输入 / 回滚备份）
```

同时会按官方 fstab 重建 `device/oppo/PLG110/recovery.fstab`。

**必须人工核对的几项**（错了会直接不开机或挂不上分区）：

1. `vendor_boot_info.json` 里 `header_version` 应为 `4`、`cmdline` 与官方一致。
2. `board_config.local.mk` 里的 `BOARD_VENDOR_BOOTIMAGE_PARTITION_SIZE`。本机为
   `100663296`（96 MiB）：官方镜像被 avbtool 补齐到**整个分区**并在末尾附 footer，
   所以 `vendor_boot.img` 的文件长度就等于分区大小（footer 里的
   `original_image_size` 是有效内容长度，A16 为 `59322368`，不要拿它当分区大小）。
   与实机复核：
   ```bash
   adb shell su -c 'blockdev --getsize64 /dev/block/by-name/vendor_boot'
   adb shell su -c 'cat /proc/partitions'
   ```
3. `recovery.fstab`：对照 `local-inputs/stock-fstab/` 原文。
   查询实机：
   ```bash
   adb shell su -c 'cat /vendor/etc/fstab.mt6993'
   adb shell su -c 'ls -l /dev/block/mapper/'   # 逻辑分区映射名
   ```

## 步骤 2：编译

### 方案 A：GitHub Actions（推荐）

把仓库推到 GitHub，然后手动触发 `Build TWRP for PLG110`，在 `firmware_url` 里填官方
固件 zip 的**直链**（或 `stock_vendor_boot_url` 只给 vendor_boot.img）。
构建完成后从 Artifacts 下载 `PLG110_twrp_vendor_boot.img`。

### 方案 B：本地 Linux / 容器

```bash
# 依赖（Ubuntu 22.04）
sudo apt-get install -y bc bison build-essential ccache curl flex g++-multilib \
  gcc-multilib git gnupg gperf imagemagick lib32readline-dev lib32z1-dev libelf-dev \
  liblz4-tool libsdl1.2-dev libssl-dev libxml2 libxml2-utils lzop pngcrush rsync \
  schedtool squashfs-tools xsltproc zip zlib1g-dev openjdk-17-jdk python3 python-is-python3
mkdir -p ~/bin && curl -s https://storage.googleapis.com/git-repo-downloads/repo > ~/bin/repo
chmod a+x ~/bin/repo && export PATH=$PATH:~/bin
```

```bash
./tools/build_twrp.sh ~/twrp-16.0
```

脚本做的事：
1. `repo init -u https://github.com/TWRP-Test/platform_manifest_twrp_aosp.git -b twrp-16.0`
   → `repo sync -c --depth=1`
2. 把 `device/oppo/PLG110`（含 `local-inputs/`）rsync 进源码树
3. `lunch twrp_PLG110-bp2a-eng` → `mka recovery vendorbootimage`
4. 用 `tools/repack_vendor_boot.py` 把 recovery 片段合并回官方 vendor_boot
5. 输出 `out/target/product/PLG110/PLG110_twrp_vendor_boot.img`

手动等价命令：

```bash
source build/envsetup.sh
lunch twrp_PLG110-bp2a-eng
mka recovery vendorbootimage -j$(nproc)
python3 tools/repack_vendor_boot.py \
    --stock device/oppo/PLG110/local-inputs/stock_vendor_boot.img \
    --twrp  out/target/product/PLG110/vendor_boot.img \
    --out   out/target/product/PLG110/PLG110_twrp_vendor_boot.img
```

`repack_vendor_boot.py` 会自己做三件事，任一项不符就报错退出（不会产出可疑镜像）：

- **保留官方其余片段**：只替换 `type=2 name=recovery` 那一段，platform 片段与 DTB、
  bootconfig 原样保留。
- **逐项校验**：header 全字段（含 `dtb_addr`）、DTB、bootconfig 必须与官方一致，
  片段必须紧邻拼接且 `vendor_ramdisk_size` 等于片段之和。
- **补齐到分区大小**：从官方 AVB footer 推出 `100663296`，把输出补零到整分区，
  这样刷进去不会残留上一份镜像的尾部数据；超了会直接报错并提示裁剪 recovery。
  要保留 TWRP 原始大小（不补齐）加 `--no-pad`。

镜像不再匹配官方 AVB 校验值。BL 解锁的机器直接刷即可；也可以加
`--avbtool <path> --avb-key <key.pem>` 用自有密钥重新签名（需要 `avbtool`）。

## 步骤 3：刷入

```bash
adb reboot bootloader

# 只刷当前槽的 vendor_boot（fastboot 默认写活动槽）
fastboot flash vendor_boot PLG110_twrp_vendor_boot.img

# 改了 vendor_boot，AVB 校验值必然不匹配，必须关校验
fastboot --disable-verity --disable-verification flash vbmeta backup/vbmeta.img

fastboot reboot recovery
```

如果卡住不动，先 `fastboot reboot` 回系统确认没坏，再考虑：

- **开不了机 / 卡 logo**：刷回官方原件即可回滚
  （`backup/` 里存了 `vendor_boot.img`/`boot.img`/`vbmeta*.img`）：
  ```bash
  fastboot flash vendor_boot backup/vendor_boot.img
  fastboot --disable-verity --disable-verification flash vbmeta backup/vbmeta.img
  ```
  备份是否被改动过可以用 `shasum -a 256 -c backup/sha256sums.txt` 核对。
- **两条槽分别刷**：`fastboot flash vendor_boot_a ...` / `vendor_boot_b`（慎用，
  只改活动槽更容易回滚）。

## 步骤 4：验证

进 TWRP 后按顺序看：

1. **能进主界面** → ramdisk 被正确加载，DTB/header 参数没问题。
2. `adb shell` / TWRP 终端里执行：
   ```bash
   cat /proc/cmdline
   ls /dev/block/by-name/
   twrp mount       # 或在 Mount 菜单勾选 system/vendor
   ```
3. 检查日志：
   ```bash
   adb shell cat /tmp/recovery.log | tail -100
   ```
4. 备份一次 boot 分区（能读能写）→ 说明块设备访问正常。

记录一下每步的现象（能进界面？触摸有反应？能挂载？），这些直接决定 `04-设备适配待办.md`
里哪些项要动手。
